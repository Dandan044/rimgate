# 导出样板视觉检查

日期：2026-10-11。检查对象为现有 `build/windows/Rimgate.exe` 与旁置 `Rimgate.pck`，版本文件标记 `2c3a117 - Art and motion review build. Full demo acceptance is pending.`。本轮没有重新导出、修改产品脚本或素材，也没有停止或重启稳定性测试 PID 87120。启动检查实例串行执行，每次只保留一个新增游戏实例，使用游戏自己的截图入口自动退出。

## 待处理问题

1. **最远镜头的关键读数不可读。** 在缩放 0.24 下，720p 的世界人物编号及炮位库存文字约 3 屏幕像素高，1080p 约 4–5 像素高；生命条高度不足或接近 1 像素，压制条更细。可以找到单位与工事的位置，却不能据此辨认编号、精确库存或人物姿态。底栏和侧栏读数正常，不能替代炮位上方完全不可读的世界反馈。证据：`build/visual_720_zoom024.png`、`build/visual_1080_zoom024.png`。
2. **全选六人时范围和路径反馈拥挤。** 两挺机枪的大射界、迫击炮射程及多条路径同时出现，交叉线覆盖大部分地图。在 1.2 近景里，目的地圈与路径还叠在“4 炮弹”标签附近。建议仅为明确选中的炮位或单名炮手显示详细范围，并给标签留出空间。证据：四张 `visual_*_zoom*.png`，近景尤见 `build/visual_1080_zoom120.png`。
3. **截图自动开始路径留有过时的准备提示。** 顶栏已为“防守进行中”，单位卡片显示“前往岗位/移动”，仍提示“准备阶段……点击开始防守”。本轮通过 `--review-auto` 复现；尚未确认普通玩家点击开始是否同样出现。证据：四张缩放端点截图。
4. **720p 辅助说明偏小。** 六张卡片、按钮、顶栏和侧栏均完整，主要数值可读；底部快捷操作提示及品牌副标题缩放后约 9 像素，视觉优先级较低但阅读费力。没有发现文字溢出或卡片被裁切。证据：`build/visual_720_zoom024.png`、`build/visual_720_zoom120.png`。

这些问题已先报告总负责人。后续提出的最低屏幕字号/条宽补偿、范围收敛与文案修订尚未包含在本轮检查对象中，不能将它们记为已修复。

## 已确认的显示行为

- 两种分辨率的顶栏、六人卡片、姿态/作战风格控件、暂停与菜单按钮、人物详情侧栏和小地图均显示完整；中文没有缺字。世界镜头缩放不改变 HUD 尺度。
- 在 1.2 缩放下，人物轮廓、头盔、阵营大色块及沙袋清楚；选择环、人物编号和卡片选中颜色可以对应到六名守军。0.24 缩放下选择环仍能帮助定位，但人物与姿态辨识显著下降。
- 姿态补充图中，05 站立、06 蹲伏，以及随后 06 卧倒、01 昏迷的形态有区别；两种分辨率下均能看出直立与横卧，蹲伏比站立更紧凑。昏迷额外使用标记和人员卡状态辅助识别。
- 机枪、迫击炮、沙袋、箱体及弹箱保持统一的简洁平涂表达。近景能读到迫击炮库存“4 炮弹”，远景标签存在上述字号问题。机枪世界库存在端点图中受镜头裁切或字号限制，未获得完整清晰读数；**本轮未验证选中炮位后的侧栏库存详情**。
- 地面没有原来的规则多边形拼贴或等距石头，草石稀疏，主要作战区留白。静态建筑、角色选择环及界面未见图集格线或明显裁边伪影。
- 近景核心和部分机枪可能在 HUD 后或镜头外。作为局部造型检查可接受；不应以近景图独自证明整体防线布局都可见。

## 日志与检查边界

对应日志为 `build/visual_*.log` 与 `build/visual_*.err`。四次端点截图保存均返回 0，没有脚本/资源错误输出。姿态检查截图也均保存成功；前三次姿态检查在截图后立即自动退出的路径出现 `4 ObjectDB instances were leaked at exit` 与 `2 resources still in use at exit` 告警，最后一次未出现。没有进一步诊断具体资源类型，不能把该告警等同于长期稳定运行内存泄漏，也不能省略它。

本轮只做静态视觉检查，不测帧率，不判断移动/转向是否平滑，不复核完整视频，不重复验证暂停时像素冻结，也不替代后台 30 分钟稳定性测试。检查完成时 PID 87120 仍在运行且响应。后续复核应在总负责人更新可读性问题并明确可用构建后进行，避免在稳定性诊断期间额外启动多个游戏实例。

逐图目视结论：

1. **最远镜头读数问题已明显解决。** 0.24 下人物编号、生命条、两挺机枪的“100 + 0”以及迫击炮“4 炮弹”不再随身体一起缩成数个像素，可以读数。站立身体仍很小，这一缩放继续适用于战术概览；不能因此声称已清楚辨认全部姿态。本轮压制均为 0，没有验证非零压制条的实际最小显示高度。
2. **全选的大范围干扰已解决；移动提示仍有局部覆盖。** 全选六人不再显示巨大的机枪射界与迫击炮射程圆。移动路径及目的地圈仍显示，符合现有移动状态；在 1.2 下，迫击炮附近的目的地圈仍叠到“4 炮弹”的部分文字上，属于尚未消除的局部可读性问题。0.24 下 04/05 靠近时，放大编号间距较紧，但仍可辨。
3. **准备提示状态不一致已解决。** 四张运行中截图均没有旧的“准备阶段……点击开始防守”提示。没有新增文案溢出。
4. **辅助说明改善，布局继续通过。** 720p 与 1080p 的底部操作说明比前轮清楚；顶栏、六人卡片、操作控件、人物侧栏与小地图均完整，没有遮住彼此或裁切。地图局部被 HUD 覆盖仍是近景构图的范围，不是控件溢出。

四次 `REVIEW_CAPTURE` 返回 0，`build/visual_fixed_*.err` 均为空；未出现前轮 motion 退出告警。所有检查实例结束后已通知总负责人可开始正式压力采样。

尚未覆盖：新固定构建的单选工事侧栏库存/占员，以及内嵌 PopupMenu 的实际弹出效果。当前截图参数没有选择工事入口，本轮不修改产品或增加外部输入脚本，因此没有将这两项记录为已通过。上述结果仅针对四张静态端点截图；前轮实际姿态截图与其检查边界仍适用。
