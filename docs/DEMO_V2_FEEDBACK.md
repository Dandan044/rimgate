# Demo v0.2 试玩反馈与后续讨论

记录日期：2026-10-12。基线为 `demo-v0.2.0`（产品导出提交 `a4b9cd6`，交付源码提交 `497b704`）。本文件记录后续意见，不表示已修改程序；原版本标签与交付包保持不变。

## C01 已确认方向：连续沙袋的沿途掩体结算

用户提供的场景中，机枪向左上方射击，弹道斜穿横向相连的多个沙袋，出现大量子弹被己方沙袋拦截的观感。[试玩截图](feedback_images/cover_diagonal_v2.png)。具体拦截比例尚未进行逐弹测量，截图不作为精确统计。

已核对当前实现：直射弹保留发射瞬间的原始枪口位置，到各沙袋首次入射边界的距离用于修正拦截概率。机枪使用机枪枪口，不使用操作员位置、底座中心或子弹当前剩余距离。当前每个独立沙袋建筑各判一次，近处出射减免随原始枪口距离增长而消失，因此同一排沙袋斜穿多格可能被重复放大。

用户确认以下改进思路，尚未实施：

1. 格子用于定位；同一段连续、同高度的掩体，不因拆成更多格子或独立建筑而获得更多次独立拦截机会。
2. 沿实际弹道，将连续穿过的相邻沙袋视为一段遮挡，整段判定一次；距离取原始枪口至整段首次入口。
3. 真正隔开的下一道掩体继续参与判定，保留多道防线的意义。
4. 合并依据为弹道上的连续穿越区间，不按地图上整个连通建筑群合并；U形阵地两侧隔着空地时仍可构成两段遮挡。
5. 斜角、厚度是否额外影响整段阻挡程度留待讨论，不直接用穿过格数进行多次独立抽样。

待细化：不同高度/材质的相邻掩体如何分段，擦角和极小间隙如何处理，混合单格/多格建筑如何取整段基础属性，以及跨仿真步和中途摧毁时的去重与失效。墙体仍独立于概率掩体机制，保持阻挡直射与流弹。

后续验证应比较相同形状拆为单个建筑或多个单格建筑的结果、正射与斜射、隔开的两道掩体及U形两侧，避免只修复截图里的单一方向。

## C02 已确认：最终命中率与Alt明细（原S01）

- 选中一名己方人员，或一座由己方人员操控的工事，再悬停敌人，默认显示一个具体的最终概率。
- 直射武器显示当前条件下单发命中该目标的综合概率，预算武器精度、距离、稳定、伤势、压制、作战风格、目标姿态/体积以及沿途全部有效掩体。单独的开火准确率不能替代该值；默认不展开计算过程。
- 按住Alt并悬停同一目标时展开计算明细。展示复用实际战斗计算和C01连续掩体分段规则，每个乘区只计算一次，不使用额外的预览随机抽样影响战斗RNG。
- 不可攻击状态需明确说明，例如超出射程、射界外或墙体阻挡。具体数值以当前状态预算，目标移动、姿态或环境改变后更新；命中与命中后造成多少伤害保持概念清楚。
- 用户已明确：迫击炮显示“目标位于爆炸范围内的概率”，不以炮弹直接命中概率或至少造成伤害概率替代。落点散布、目标位置/体积与爆炸范围须按曲射规则预算，不能套用直射掩体乘积。是否对飞行期间移动作预测及其展示口径留待细化。

待细化：尚未开始瞄准时采用当前稳定值还是预计开火值、多选时如何展示，以及干扰实体和动态弹道对预算的处理。验证需将固定场景预算与实际弹丸采样对照。

## C03 已确认：状态栏预计死亡时间（原S03）

状态栏展示按当前生命和持续失血计算的预计死亡时间，基础为 `当前HP / 每秒失血`。这是预计死亡时间，不是到达昏迷阈值的时间；单位采用游戏时间，暂停时冻结。没有持续失血时显示稳定状态，不给出虚假的死亡倒计时。说明不包含后续受击或尚未完成的治疗影响。

本轮明确采纳的是状态栏时间提示；此前建议的额外救援路线等展示尚未逐项确认。

## C04 已确认方向：每人独立火力控制（原S04）

每名人员可独立控制开火模式/策略，与“压制、常规、谨慎”的作战风格分开。采纳原建议中的停火/恢复开火，以及严格锁定和优先攻击的区分；严格锁定目标暂时无效时仍守位等待。具体模式名称、目标优先级界面、工事如何设置或继承火控，以及该“模式”是否还包含单发/点射/连射等机械射击方式，留待细化，不倒写为已经确认的按钮规格。

## C05 已确认方向：空闲自动装填与提前预装

处于征召状态且没有寻敌/交战任务时，自动装填武器，包括有人操作的工事和迫击炮。迫击炮应提前装膛，不能等玩家指定目标或落点才开始装填；装膛不等于自动发射，保留既定的一次命令一枚炮弹。

已核对基线：步枪和机枪空仓时可以在没有目标的情况下换弹，但有剩余弹药时不会主动补满；迫击炮在没有轰击命令时提前返回，确实不会自动预装。

需细化部分弹匣/弹链的补满条件、空闲的定义、敌人出现时是否中断，以及换弹过程中移动或岗位换人的处理。装填继续花费实际时间、占用可工作的操作员并遵守库存与弹药守恒；准备暂停期间只规划，不推进装填时间。

## Q01 现状核对与待讨论：自动姿态

当前 `_auto_posture` 在非手动锁定、非强制伏低、非姿态切换和非溃逃时，仅返回站立。它没有按威胁、掩体或射击条件主动选择蹲伏/卧倒。

压制反应是另一个机制：压制达到60时强制卧倒并中断相关工作；至少1.5秒且压制降至40以下后解除，自动模式恢复站立，手动模式恢复用户选择的姿态；达到100触发溃逃。这个强制反应对手动姿态同样适用，因此目前“自动”没有鲜明的独立决策作用。

开发方候选方向，尚未确认：移动时优先站立；停下交火时选择可射击的较低姿态；持续威胁时伏低；威胁解除后延时恢复，并设置迟滞以免反复起落。操作工事、搬运和救援须遵守动作条件，不能自动改变玩家指定位置。

## C06 已确认目标：美术资源细化与整套UI重设计

用户反馈当前战场贴图过于简陋，UI空白过多、占用屏幕过大。本项作为完整的视觉与信息布局重设计，不能仅换配色、缩小字体或增加零散装饰。

保留此前认可的人物基本轮廓与配色作为起点；细化地面、建筑、人物装备和动作等资源。制作手段可采用SVG、AI生图或适合的其他资源制作方式。具体新样式尚未确认。

候选制作顺序：先形成同时包含人物、工事、地面与HUD的一张完整战场视觉样板，再按统一尺度、光照、描边与材质语言制作素材。SVG适合人物/工事可控轮廓、图标和UI；AI生图可提供地表、残骸和材质样稿，筛选及整理后再作为游戏素材，不直接铺满未经统一的图像。

候选UI布局：窄顶栏保留暂停、时间、核心和波次；底部紧凑小队卡与情境操作；详情面板按选择和内容展开；小地图可收起；操作提示减少常驻占位。Alt命中明细按需出现。布局、尺寸和素材清单均为方案草案，不表示已经制作完成或批准所有细节。

## C07 已确认方向：暂停落点预览与右键拖动队形

- 暂停时多人移动指令就应分配各自合法格子，并显示每个人实际将到达的位置，不能统一显示同一个点，到恢复运行才看见分散。
- 代码核对发现，`validate_order` 已生成每人的 `_allocations[id].goal` 并保存至待执行命令；但 `_draw_orders` 对所有人读取公共 `order.data.position`，因此当前暂停预览与内部预分配不一致。需让规划、显示与执行共用落点数据。
- 选中多人，在地面按住右键拖动，调整站位展开程度和方向；拖动时实时显示各人的格子落点，松开确认。短点击保留普通移动。
- 继续满足格心落点、一格一名活动单位、不可停留掩体、障碍/已占用格及可达性检查；暂停规划不推进仿真。恢复后不能无故重新排列站位，动态变化导致原落点不可用时再合法修正。
- 新右键仍应优先解除旧菜单/选点状态；地面队形手势和人物/工事交互需要兼容。

待细化：拖动方向对应队列轴线还是人员面朝方向、长度与间距的映射、人员与位置的匹配，以及空间不足时的提示和修正方式。

## C08 已确认平衡方向：拉开三种作战风格

用户试玩反馈压制射击射得快且仍较准，收益偏高；谨慎射击精度收益偏低。方向确定为进一步降低压制准确率、进一步提高谨慎准确率，具体倍率尚未确定。

当前精度倍率以常规为1：压制0.65、谨慎1.25。常规步枪每轮3发、周期约3秒；谨慎每轮1发、周期约4.5秒，因此收益比较不能仅看精度倍率。后续在同距离、目标姿态、掩体、稳定和压力条件下，比较每发命中、有效命中/时间、耗弹及压制效果；参数调整与C01掩体规则更新一起复核。常规约3秒一轮的既定目标保留。
