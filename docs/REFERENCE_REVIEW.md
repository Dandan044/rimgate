# RimWorld 参考调研与 Demo 方向修订

日期：2026-10-11。性质：参考调研、现有工程诊断和修订方案；不是已完成的修复报告。

用户反馈：当前画面偏像素风，未达到 RimWorld 式表达；时间推进有顿挫，像伪即时或回合制。这里的“连续”指实时运动和并行行动的观感。

本轮停止扩充玩法和批量制作素材，只核对参考、代码、已有截图与性能记录。现有版本不作为美术或流畅度验收通过的版本。

## 1. 已核实的参考

### 美术表达

Tynan 在 2013 年的官方美术说明中明确强调简洁、图标化和矢量观感，要求小尺寸下传达人物身份、阵营、朝向、衣着与动作信息。该说明是设计原则的依据，不代表所有现版本素材都没有纹理或渐变。[开发者原文](https://ludeon.com/blog/2013/12/rhopunzel-in-the-house/)

本轮在浏览器实际查看了官网的[角色截图](https://rimworldgame.com/images/screens/rimworld-colonist.jpg)和[战斗截图](https://rimworldgame.com/images/screens/rimworld-mechanoids.jpg)。视觉观察：角色以头部和简化身体形成清楚轮廓；建筑以可辨认的大形状组织空间；物体边界、装备和朝向比微小表面细节更突出。场景确有纹理、阴影和明暗，并非所有东西都是无纹理的纯色几何图形。

### 引擎与时间

官方 FAQ 说明使用 Unity、C#，并自行实现对象与时间管理。Tynan 在 2013 年说明对象框架使用固定步长，2014 年帖子提到当时每步为 1/60 秒。这些历史说明支持固定步长仿真的方向，不能据此断言当前版本每个内部系统的具体实现。[官方 FAQ](https://ludeon.com/blog/faq/)、[2013 年引擎说明](https://ludeon.com/forums/index.php?topic=258.0)、[2014 年时间步长说明](https://ludeon.com/forums/index.php?topic=3087.15)

固定步长并不要求单位逐格跳跃或轮流行动。地图格子可以定义建筑占地、寻路拓扑与查询范围，屏幕位置仍可连续变化。这是我们工程的实现选择；没有证据表明必须更换到 Unity 才能获得目标体验。

Godot 官方文档区分物理更新与显示帧，并介绍通过前后状态插值平滑运动；CPU/GPU 瓶颈造成的低帧率则需要另行优化。插值不能把每秒 6 帧变成每秒 60 帧。[插值原理](https://docs.godotengine.org/en/stable/tutorials/physics/interpolation/physics_interpolation_introduction.html)、[抖动与卡顿](https://docs.godotengine.org/en/stable/tutorials/rendering/jitter_stutter.html)

尚未核实：RimWorld 当前版本的具体显示插值、移动动画与内部调度细节。本轮未完成官方视频逐帧分析，不能把下文的 Godot 方案描述成 RimWorld 源码复刻。

## 2. 当前工程的问题与证据

### 画面偏离

检查对象：`build/c_review1080.png`、`build/c_reviewzoom.png`、`build/review720.png`，角色/地面图集及其生成提示词，`scripts/ui/world_view.gd`。

- 当前人物带有完整四肢、靴子、细碎护具与密集明暗，更接近微缩军事插画。缩小后这些细节挤在一起，核心轮廓反而不清楚。
- 地面以密集细颗粒覆盖大面积屏幕，单位与工事没有得到足够的视觉优先级。需要控制纹理的频率和对比度，而非仅改变颜色。
- 默认镜头缩放为 0.42；普通人物绘制画布为 76×76 世界像素，透明留白又进一步缩小有效身体。源图分辨率大不等于屏幕中的角色清楚。
- `world_view.gd` 已使用线性过滤。不能把风格偏离全部归咎于最近邻过滤或 PNG 格式，也不能只改一个导入开关就宣称解决。
- 我们此前没有在批量制作前落实小场景的实际观感验收。这是流程上的缺口。

### 连续感不足

代码检查发现：

- `battle_screen.gd::_physics_process` 每次调用 `world.step(Config.FIXED_DT)`，配置为每秒 60 步。移动、射击与其他工作按各单位自身状态并行推进，未发现全局轮流行动的回合队列。
- `world_view.gd::_draw_unit` 直接绘制 `u.pos * GRID`，弹丸也直接读取仿真位置。虽保存了 `prev_pos` 用于碰撞，但视图未用它平滑显示。
- 角色纹理在四个朝向间直接切换，姿态图片也直接切换。移动仅有小幅上下摆动，缺乏连贯的动作过渡。
- AI 每 0.25 秒重新决策；移动仍在每个固定步中推进。因此不能直接把 0.25 秒决策间隔当作全部顿挫的原因。
- 姿态切换有 0.35/0.7 秒局部动作时间，压制也会打断行动。寻路转角、拥堵避让和姿态自动调整都需分别观察，防止反复切换导致停走；当前尚未逐项量化其贡献。

已有压力测试 `build/reports/benchmark.json`：6 名友军、24 名敌军、维持 256 个投射物，预热 5 秒、采样约 60 秒。平均 6.12 FPS，平均帧时间 163.34 ms，P95 178.92 ms；硬件为 Ryzen 7 9800X3D / RTX 5070。记录的逻辑视口为 1600×900，不能把它写成已确认的原生 1080p 渲染性能。

该压力测试明确未通过，但不能替代用户刚才普通游玩场景的帧率数据。当前弹丸处理包含遍历单位和建筑的候选检查，应优先剖析；尚不能仅凭代码就认定所有耗时都来自此处。

结论：当前实现使用实时仿真，但显示平滑、动作连贯性及负载性能均存在问题。用户感受到的“伪回合制”是需要消除的实际体验问题，不能用实现名词否定。

## 3. 修订方案（待实施）

### 美术

1. 用原创 SVG 优先制作基础人物、沙袋、墙体、箱体和机枪：统一轮廓、比例、描边与色板，人物强调头部、身体、装备大形状。
2. 站立人物采用简化身体，避免以完整四肢的细节撑起辨识度；蹲伏、卧倒和倒地仍须明显可辨。武器单独分层，朝向与实际射击方向一致。
3. 地面采用低对比底色和少量成组的地表变化，保留必要纹理；减少均匀铺满屏幕的细噪点。人物、工事和命令反馈优先于背景装饰。
4. AI 生图可用于符合上述规范的底稿或补充资源，先放入实际场景验证比例、轮廓与缩放，再决定是否扩充。验收针对画面结果，不以工具、文件格式、生成数量或源图清晰度代替。
5. 首批人物、武器、工事与地面必须一起验收；现有军事图集只保留为可回退的旧素材，不继续按其规格批量扩展。

### 时间、显示与性能

1. 保留固定 60 Hz 战斗计算；AI 的目标选择可较低频更新，移动、装填、治疗及射击计时仍连续推进。
2. 将显示状态与结算状态分开。对于当前自定义 `_draw()`，逐实体保存显示所需的前后位置，以 `Engine.get_physics_interpolation_fraction()` 插值；仅开启 Node2D 的插值开关不会自动处理字典内每个单位的位置。
3. 人物、武器、弹丸、携带物与选中反馈使用一致的显示坐标。转向和姿态过渡只影响表现；真实射界、受击体积和完成时间仍由仿真决定。
4. 暂停冻结世界表现，镜头与选择继续响应；重开、生成、瞬移和携带关系改变时重置显示历史，避免从旧位置滑过去。相关实现遵循 [Godot 插值使用说明](https://docs.godotengine.org/en/stable/tutorials/physics/interpolation/using_physics_interpolation.html)。
5. 分别采样单位、AI/寻路、弹丸碰撞、绘制、HUD 与测试夹具耗时；优先验证空间分区查询、静态建筑缓存和地面绘制缓存的收益，保证扫掠碰撞、友伤与掩体规则不变。
6. 核查近距离路径点、转弯、窄路避让和自动姿态反复触发。调整动作表现前先辨别是合理瞄准/装填，还是意外停走；某人的局部动作不能让其他单位一起等待。

## 4. 恢复完整 Demo 开发前的验证

先做小场景验证，不改变完整 Demo 的 6 人守卫目标：

- 一个友军、一个敌人、一段沙袋、一面墙、一挺机枪与一块地表；展示站/蹲/卧和武器分层。
- 以实际游戏缩放展示 720p、1080p 的画面：看清阵营、姿态、装备和掩体，人物不依靠放大源图才可辨认。
- 连续录制至少 20 秒移动、转弯、移动射击与不同单位并行行动，并包含暂停和恢复；同时记录帧时间。先确认基础观感，再扩充素材。
- 用不同显示帧率检查平滑，开发检查中临时降低固定步频暴露插值错误；降低步频仅为诊断，不作为最终性能补丁。
- 普通交战和压力场景分别报告。沿用完整 Demo 的平均 60 FPS、P95 ≤33.3 ms 性能门槛，记录实际窗口/渲染分辨率；不靠删除结算弹丸或隐藏失败记录通过。

本轮产出到此为止：调研记录与开发计划修订。未更换素材、未修改战斗逻辑、未声称性能或观感已经修好。

## 5. 后续修订进度（2026-10-11）

上述结尾描述的是调研轮次。随后已实施原创 SVG 人物与工事样板、安静的静态地面、人物与弹丸的显示插值；修复路径点丢失剩余移动距离与姿态过渡额外停走。弹丸保留本步终止轨迹，命中、落地爆炸和新生弹片按同一显示时刻出现。暂停、恢复、重开和携带关系改变均处理显示历史。

碰撞查询加入保持原遍历顺序的空间分区，保留穷举实现作精确对照；282 步场景的状态与随机数结果一致，80,000 发统计不变。后续更新敌人选位、岗位补给与战斗合同；现行 AI 的独立 Windows 压力运行达到平均112.02 FPS、P95 14.892 ms（硬件、负载和实际渲染分辨率见测试报告）。这是已测性能，不能替代完整试玩验收。

当前只细调既有样板，不扩充美术数量。新录像用于复核连续移动、转向、姿态、并行动作与暂停恢复；固定帧率录像本身不作实时性能证据。最新执行项、限制与待办统一记录于 [测试报告](TEST_REPORT.md)。

## 6. 用户确认的方向（2026-10-12）

用户选择：“保持这轮轮廓和配色，继续细调”。因此保留当前原创 SVG 人物和工事的大形、比例与色板，后续集中处理字号、库存与人员标记重叠、姿态和运动反馈，不再增加一批不同风格的素材。这是造型方向确认，不能替代整个 Demo 的最终体验验收。
